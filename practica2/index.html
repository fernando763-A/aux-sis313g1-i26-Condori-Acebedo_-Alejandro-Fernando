Preguntas y Respuestas

1. ¿Qué es Git y cuál es su función principal dentro de un proyecto de desarrollo?

Respuesta: Git es un sistema de control de versiones distribuido que permite registrar y administrar los cambios realizados en los archivos de un proyecto de software.
Su función principal es mantener un historial seguro de todas las modificaciones, lo que facilita: Guardar versiones del código y volver atrás si ocurre un error.

2. ¿Cuál es la diferencia entre Git y GitHub y qué función cumple cada uno?

Respuesta: Git: es un programa que se instala en tu computadora. Su función es llevar el control de versiones de tu proyecto, guardando cada cambio en forma de commits, permitiendo trabajar con ramas y recuperar versiones anteriores.
GitHub: es una plataforma en línea que utiliza Git, pero además ofrece un espacio en la nube para almacenar repositorios y colaborar con otros. Permite compartir tu código, trabajar en equipo, revisar cambios y publicar proyectos.

3. ¿Qué pasos se deben seguir en Git para guardar los cambios realizados en un proyecto y crear un commit?

Respuesta:
Verificar el estado del repositorio
git status
Agregar los archivos al área de preparación (staging area)
Para un archivo específico:
git add nombre_archivo.html
Para todos los archivos modificados:
git add .
Crear el commit con un mensaje descriptivo
git commit -m "Agregada página index.html con horarios"
(Opcional) Subir los cambios al repositorio remoto (GitHub)
git push

4. ¿Qué comandos se utilizan para conectar un repositorio local con un repositorio de GitHub y posteriormente subir los cambios? Explique brevemente la función de cada uno.

Respuesta:

  1. Conectar el repositorio local con el remoto (GitHub)
    git remote add origin https://github.com/usuario/nombre-repositorio.git
    Este comando enlaza tu proyecto local con el repositorio remoto en GitHub.
    origin es el nombre que se le da por defecto al remoto.
    La URL es la dirección de tu repositorio en GitHub
  2. Verificar la conexión
    git remote -v
    Muestra las direcciones del repositorio remoto para confirmar que está bien configurado.
  3. Subir los cambios por primera vez
    git push -u origin main
    Envía tu rama principal (main) al repositorio remoto.
    -u establece la rama remota como predeterminada, así después solo necesitas usar git push.
  4. Subir cambios posterioares
    git push
    Actualiza el repositorio remoto con los commits nuevos que hayas hecho en tu rama local.

5. ¿Qué es una rama (branch) en Git y en qué situaciones puede ser útil trabajar con una rama diferente a main?

Respuesta:Una rama (branch) en Git es una línea de desarrollo independiente dentro de un repositorio. En otras palabras, es como una copia paralela del proyecto donde puedes trabajar sin afectar directamente la versión principal (generalmente llamada main).

6. Explique el proceso para crear una nueva rama, realizar cambios en ella y posteriormente subir esa rama a un repositorio de GitHub.

Respuesta:

  1. Crear la rama
    git branch nombre_rama
    Crea una nueva rama en tu repositorio local.
  2. Cambiarte a la rama creada
    git checkout nombre_rama
    Te mueve a esa rama para empezar a trabajar en ella.
  3. Realizar cambios en los archivos
    Edita o agrega archivos en tu proyecto (por ejemplo, index.html, horario_materias.html, horario_auxiliatura.html).
  4. Guardar los cambios en la rama (commit
    git add.git commit -m "Agregados archivos de práctica 2 en rama auxiliatura"
    git add . prepara todos los archivos modificados y git commit guarda los cambios con un mensaje.
  5. Subir la rama al repositorio remoto (GitHub)
    git push origin nombre_rama
    Envía la rama al repositorio remoto en GitHub.

7. ¿Qué es un conflicto en Git y qué pasos se deben seguir para resolverlo antes de combinar los cambios de una rama con main?

Respuesta:Un conflicto en Git ocurre cuando dos ramas han modificado la misma parte de un archivo de manera diferente y Git no puede decidir automáticamente cuál versión

  1. Intentar la combinación
    git merge nombre_rama
    Si hay conflictos, Git lo notificará y marcará las secciones problemáticas en los archivos
  2. Abrir los archivos en conflicto
    <<<<<<< HEAD código de la rama main ======= código de la rama auxiliatura >>>>>>> auxiliatura
    Indican las dos versiones que chocan
  3. Editar manualmente el archivo
    Elimina las marcas (<<<<<<<, =======, >>>>>>>) y decide qué parte del código conservar, o combina ambas si es necesario.
  4. Marcar el conflicto como resuelto
    git add nombre_archivo
    Esto indica que el archivo ya fue corregido.
  5. Finalizar el merge
    git commit
    Crea un commit que registra la resolución del conflicto.
  6. Subir los cambios al repositorio remoto
    git push
    Actualiza la rama en GitHub con la versión corregida.
